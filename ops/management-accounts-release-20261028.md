# 平台管理中心：帳號建立、補建、綁定與安全刪除（第 1 批）

狀態：**程式已修改、本機測試通過；尚未部署、尚未套用正式資料庫、尚未使用者驗收。**
基底：正式 main `d8131275ba6883340c2a9d1049c007c5ddb2256c`（10.27-ADMIN.1）。版本：前端與 Edge `10.28-ADMIN.1`。

## 一、查到的真正原因

| 現象 | 原因 |
|---|---|
| 仙女無法建立管理帳號 | 管理登入只有「總裁密碼」與「主播代碼＋密碼」兩種；仙女空間沒有任何主播資料，所以沒有東西能設密碼。10/26 版明列不含「建立新管理帳號、空廳首位主播建立」。 |
| 帳號搜尋找不到 | 舊搜尋只列已登入過且有管理職務的帳號，正式環境 4 個全在聲瑪。主播帳號原本要等第一次登入才會產生 Account。 |
| 仙女「尚需完成營運啟用設定」 | 不是漏填欄位。管理中心新建的空間一律存成停用，`restore` 硬性回 `SPACE_PROVISIONING_REQUIRED`；點歌、存歌、帳務等營運路徑目前只允許 `space-001`（聲瑪）。這屬第 2 批「新空間營運啟用」。 |
| 只能刪除檢查 | 永久刪除從未實作；舊的刪除原型預設拋出 `DELETE_PROTOTYPE_ONLY`，且任何未盤點資料表都會阻擋（死路）。 |

## 二、本批完成內容

- 每張廳、廳內主播、獨立主播卡片直接提供：建立登入帳號／登入設定、綁定已有帳號、編輯資料、編輯管理權限、進入管理後台（營運中的空間）、查看專屬首頁、紅色刪除。全部使用原位彈窗，手機與桌面皆可操作。
- 建立獨立主播：一次送出、一個資料庫交易，同時建立空間、主播資料、登入代碼與密碼、管理帳號與授權。不要求選擇所屬廳。
- 新增廳內主播：可同時建立主播登入帳號。既有主播（含仙女建立主播資料後）可事後補建或重設登入。
- 主播登入帳號在建立當下就產生正式 Account、管理連結與主播授權，並立刻出現在「管理帳號」頁；第一次登入沿用同一個 Account。登入代碼與密碼沿用原有 `papa_manage_streamer_login`（bcrypt、不可與總裁密碼相同、會讓舊登入失效）。
- 「管理帳號」頁列出全部空間的管理帳號，可搜尋名稱、登入代碼、空間名稱，顯示每個空間的身分；可「綁定到空間」，同一帳號多空間權限各自獨立。
- 刪除：先自動檢查，再依結果顯示
  - 無重要資料：列出「將移除」與「會保留」，需輸入名稱確認後永久刪除。
  - 有重要資料（存歌、帳務、演唱、歌本、勳章、私訊、留言、收藏、專屬提歌權、玩家資料引用、未知資料表等）：逐項列出筆數，不允許刪除，提供「停用並封存」或「停用空間」。
  - 廳內仍有主播：列出受影響主播，不自動連帶刪除。獨立主播空間會明確標示連同其唯一主播一起刪除。
  - 聲瑪 `space-001` 與原始主播 `papa` 一律不可刪除。
- 營運啟用設定：在同一彈窗列出主播資料、登入帳號、營運功能、專屬網址各項狀態與可直接處理的按鈕；不繞過會員方案或權限、不開通未授權功能。
- 新空間主播嘗試登入時，顯示「此空間的營運功能尚未開放；登入帳號已建立」，而不是誤導為密碼錯誤。

## 三、資料庫變更（`supabase/migrations/20261028041500_management_accounts_and_deletion.sql`）

全部為新增，不改寫任何玩家、歌曲、待播、帳務、勳章、通知或 Audit 資料列；開頭會檢查必要物件，缺少即中止。

- `papa_spaces.deleted_at`、`papa_space_streamers.deleted_at`（可為空的墓碑欄位）。
- `papa_management_deletions`：刪除封存紀錄（不含密碼或雜湊），禁止更新與刪除。
- 觸發器：已刪除的空間／主播不能被改名、復活、加入成員，也不能再寫入業務資料。
- 新函式（僅 service_role 可執行，函式內再次驗證總裁 Account、平台角色與總裁登入連結）：`papa_management_provision_streamer`、`papa_management_streamer_login`、`papa_management_streamer_login_status`、`papa_management_account_list`、`papa_management_delete_review`、`papa_management_delete`、`papa_management_space_readiness`。內部函式不授權給 service_role。
- `papa_space_center_directory`：與 10/26 版相同合約，另排除已刪除墓碑，並提供登入與帳號就緒欄位。

為什麼用墓碑：管理 Audit、事件歷史與舊網址紀錄依設計不可修改，且以外鍵指向空間／主播。刪除後這些列保留作追查，對應的空間或主播 ID 保留為不可使用的墓碑，舊網址與 QR 不會被別人接手；其他設定、登入、授權、主播資料全部移除。

## 四、測試（本機）

本工作環境無法下載 npm 套件，`@electric-sql/pglite` 改以本機 **PostgreSQL 16** 相容層執行原有資料庫測試（每個測試獨立叢集）。

- 新增 20 項測試全部通過：
  - `tests/management-accounts-deletion.test.js`（8 項，真實 PostgreSQL）：獨立主播一次建立並**實際登入**成功；聲瑪與新廳主播建立即可登入；既有主播補建帳號後登入；停用登入後無法登入；重複代碼、弱密碼、與總裁相同密碼、壞代碼、私有欄位全部原子回滾；非總裁一律拒絕；anon／authenticated 無執行權；帳號清單跨空間；無資料測試主播永久刪除且玩家、其他主播、業務資料不變、事件歷史保留、帳號停用、刪除後不能登入或寫入；有資料、玩家引用、未知關聯、原始主播與聲瑪一律擋下；廳不連帶刪除；空廳與獨立空間刪除成墓碑；目錄隱藏墓碑。
  - `tests/management-provision-edge.test.js`（5 項）：Edge 只用驗證過的總裁 Account、密碼不進入 payload、欄位驗證、打包後的 Edge 分派與錯誤訊息。
  - `tests/management-center-actions-ui.test.js`（7 項）：卡片操作、獨立主播表單無所屬廳、密碼不一致攔截、成功後提供進入管理後台、重送沿用同一操作 ID、密碼不留在畫面狀態、刪除與封存流程、帳號頁綁定、營運啟用設定。
- 兩個資料庫連線的並發驗證：同時建立相同登入代碼只有一個成功；刪除與同時寫入業務資料 6 輪皆不會同時成功（不是刪除被擋，就是寫入被擋）；同一刪除操作 ID 並發送出只有一次效果。
- 回復 SQL 與重新套用皆已實測。
- 完整測試：1,477 項通過、222 項失敗；**失敗清單與修改前基準相同**（基準 1,456 通過、223 失敗，多為舊測試未跟上程式，與本批無關），本批未新增任何失敗。
- 網站建置與 Edge 打包通過。手機 390px、桌面 1280px 彈窗截圖檢查正常（以模擬資料）。

## 五、上線順序（需核准，正式環境操作請由有權限者執行）

1. 執行唯讀預檢：`ops/management-accounts-preflight-20261028.sql`。所有 `*_ok` 為 true，`not_yet_applied` 為 true，記下各項數量。
2. 套用 migration `20261028041500_management_accounts_and_deletion.sql`。完成後再跑一次預檢的數量查詢，空間、主播、登入、帳號、職務、Audit、業務資料筆數應完全不變。
3. 部署 Edge `party-api`（`node build-edge.mjs` 產生的 `deploy-function.txt`），確認 `releaseInfo` 回報 `10.28-ADMIN.1` 與 `managementProvision:1`。
4. 發布前端（GitHub Pages）。確認 `v2.html` 載入 `app.js?v=10.28-ADMIN.1`。
5. 正式驗證（使用隔離測試資料，完成後刪除；不可刪除聲瑪、仙女或其他正式空間）：
   - 建立「測試廳-1028」→ 新增廳內主播並建立帳號 → 用該代碼與密碼登入成功 → 刪除主播 → 刪除廳。
   - 在聲瑪新增「測試主播-1028」並建立帳號 → 登入成功 → 從管理中心「進入管理後台」→ 刪除。
   - 建立獨立主播「測試獨立-1028」→ 確認帳號出現在「管理帳號」→ 登入時顯示「營運功能尚未開放；登入帳號已建立」→ 刪除。
   - 仙女卡片按「建立主播資料與登入帳號」完成補建（這是正式資料寫入，由總裁本人操作）。
   - 對有資料的正式主播按刪除，只看檢查結果：應列出阻礙且沒有刪除表單，按關閉離開。
   - 手機與桌面各開一次彈窗。

## 六、回復

- 前端與 Edge：還原到 `d8131275` 的版本。
- 資料庫：`ops/management-accounts-rollback-20261028.sql` 移除新函式與觸發器、還原 10/26 目錄函式；保留刪除封存表與墓碑欄位（它們是已執行刪除的紀錄）。已建立的主播與登入帳號回復後仍可正常使用。不需回復任何業務資料。

## 七、明確不包含（後續批次）

- 第 2 批：新空間營運啟用（仙女等新空間的歌本、待播、點歌、存歌、帳務、玩家登入）。目前十多個 Edge 入口與多個 SQL 路徑只允許聲瑪，需逐一開放並驗證。
- 第 3 批：廳管理員專屬登入帳號（登入代碼＋密碼）、一個帳號多身分切換、管理中心依權限開放給廳管理員。
- 含正式業務資料的永久刪除：需先做「資料備份 → 驗證可還原 → 相依資料處理 → 再次確認」流程，另批實作；本批對這類對象只提供封存或停用。
