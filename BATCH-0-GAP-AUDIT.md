## Phase order and migration boundary

1. **Phase 0:** preserve current production baseline and this audit; complete Issue #1 branch validation before integrating it. No production schema or site change in this phase.
2. **Phase 1:** add Account, Space 001 and Membership with compatibility mapping; add policy/feature/device/session/notification/deep-link contracts. Keep old streamer-scoped reads and writes operational during the transition. Test identity and cross-Space denial before moving clients.
3. **Phase 2:** Web routes/auth/session and low-Egress reads adopt the new contracts; retain existing working Web Push until the replacement is verified.
4. **Phase 3:** finish business gaps in Issue #11, including catalog governance, venue pools, effective-time quota, and Issue #7 achievements. Awards must be derived from canonical events, respect streamer/Space scope, preserve historical timestamps, and exclude cancelled medals.
5. **Phases 4–6:** Android with FCM, then Desktop shell, then platform entry/Space UX. Reserve an iOS adapter contract without building an iOS app.
6. **Phase 7:** one data-preservation and cross-Space integration pass, full regression/builds, then one production migration and deploy with smoke tests.

Largest **data risk**: retrofitting `space_id` and account identity into a live shared-player/streamer model could leak one tenant's credits, queue, private messages, lyrics or audit rows, or silently rebucket history. Mitigation: additive keys, validated mapping, transactions, per-role/RLS tests and production snapshot comparison.

Largest **Egress risk**: multiplying visible-page timers by devices/spaces (board 8 s, app 30 s, chat's disconnected 4 s fallback), then introducing native clients. Notification polling is now a 30 s **disconnected/stale-Realtime fallback only**; connected broadcasts and visibility resume trigger timely reads without duplicate periodic requests. While Realtime is healthy, new-message notices refresh the open chat immediately and its timer only catches up read receipts once per minute; a disconnected client retains the previous 4 s chat fallback. Board polling and whole-app refresh still need measured, scoped replacement. Mitigation: scoped Realtime for foreground deltas, Push for background, lifecycle cleanup, selected-field bounded catch-up, and network/billing measurement. Preserve current notifications while replacing transport.

## Achievement handoff for Phase 3

[Issue #7](https://github.com/lacylovebap-cell/papa-party/issues/7) supersedes the older ChatGPT draft for retained/deleted medal names. The current `achievements()` is a computed display helper, **not** durable award history. The first-mic rule currently looks at first accepted request rather than first completed performance; the night rule currently needs reconciliation with the 01:00–05:00/5-song requirement. The eligible failed-request event is deduplicated in `202609240002_failed_request_event.sql`, but it is not yet a persisted medal award. Do not backfill acquisition times by inventing history. Phase 3 needs a Space/streamer/player-scoped award key and source event/effective-time snapshot, idempotent recalculation, visibility mode, award notification, and tests for cancellation, test accounts, no-credit attempts and the deleted-name list. The unnamed 50-song medal must wait for a final name rather than shipping a guessed title.

**Phase 1 bridge drafted locally:** `202610070001_space_foundation.sql` creates Account/Space/Membership registry tables, tags legacy operational entities as Space 001 without changing their JSON, preserves legacy streamer creation, and refuses unknown/cross-Space writes. `202610070002_device_sessions.sql` adds service-only installation and durable session storage with distinct player/manager scope, active-membership validation, atomic hashed refresh rotation and account-scoped revocation. `202610070003_verified_identity_binding.sql` binds a legacy session to a stable Account only after the existing password check succeeds, and makes access/Push authorization check active membership and the requested room on one bounded server lookup. `202610070004_audit_actor_snapshots.sql` separates new actor Account/role/name from target player snapshots without rewriting old rows; the bounded event page returns both in one read. `202610070005_device_push_contract.sql` reserves Web Push/FCM/Desktop/APNs registrations per durable installation-bound session, with idempotent delivery IDs and service-only Space/recipient checks. `202610070006_device_access_lifecycle.sql` adds atomic device start/refresh/logout; changed passwords revoke the matching long-lived devices and issued access sessions. `202610070007_notification_space_scope.sql` backfills and guards notification Space ownership without rewriting bodies, IDs or read state. `202610070008_policy_feature_entitlement.sql` reserves service-only Space policy, feature and Account entitlement tables with a membership-checked bounded snapshot; it creates no entitlement for old features and does not activate billing or new gates. The Edge exposes device methods and passes the effective room into the Account/Space authorization check, including its default room. The Web has **not** switched to storing a long-lived credential; a safe GitHub Pages storage approach and native secure-store adapters remain Phase 2/4/5 work. Existing Web Push stays active; new delivery is not auto-enqueued yet. Focused tests pass for preservation, scoped writes, stable and separate identities, suspension, audit attribution, duplicate delivery prevention, multiple devices, replay denial, logout/password revocation, anonymous denial, cross-Space denial/allowance, policy isolation and transactional rollback on unmappable legacy rows. These migrations are **not applied to production**; Web client adoption and full Space 002 business routing are not yet delivered.

Every live row in `songs`, `ledger`, `queue`, `cards`, and `crowns` had a nonempty `streamer_id`; no `wishes` row was present. All 1,057 notifications map to one of the eight known streamers; none was orphaned. No private row content was fetched, and no production schema or data was changed. This verifies two missing-streamer preconditions on the present data, but it does not replace a transactional migration dry run or a before/after preservation check.

**Compatibility boundary:** Space 002 device identities can be issued and verified in isolated tests, but the old business snapshot is explicitly limited to Space 001 until Phase 2 introduces scoped reads/writes. A Space 002 token cannot fall through to the default `papa` room or load the legacy snapshot. Legacy logout no longer loads that snapshot; a durable device token must use its refresh-protected device logout.

**Audit identity bridge:** New ordinary events take the verified Account from the request context. New shared-catalog events resolve the existing server-derived `president`, `streamer:<id>` or `player:<id>` actor key to its Account inside the event trigger. Actor name, target player and room/Space stay separate; old rows remain unchanged and unknown when identity was not recorded.

**Scoped read addition:** `202610070009_scoped_read_snapshot.sql` adds a room-indexed ordinary-read RPC. It returns global meta/settings/shared players plus only the requested streamer's songs, ledger, queue, crowns, cards and wishes, removing lyric/private-note bodies from songs. The Edge uses it only for changed/forced page reads; login, mutations and backups keep the complete compatibility snapshot. The Space 002 business barrier remains until the full scoped write and routing path exists. A two-streamer local SQL fixture verifies that neither room's rows enter the other's read response; the Edge test checks that the requested room reaches the RPC.
