# 10.12-WEB.4 — players manage their own cross-host waiting requests

Player Center now lists the authenticated player's unfinished saved/live requests across the current Space, with current-host requests first. It reads only the requested server page of at most 20 rows. Sorting, page jumps and cross-page selection are retained; switching Account, player, Space or current host clears the selection and invalidates late responses. Each row provides replacement and cancellation; selected cancellations are limited to 50 requests across 10 hosts. Inactive-host requests remain visible and cancellable.

Replacement preserves the original request ID, owner, request time, venue, provenance and financial/history links. The selected host's visible songbook supplies replacement choices, including existing half-song pairing rules. A read-only quote checks current crown/gift fees, saved-credit reservations and the original hour's capacity before submission. The server revalidates these rules under the original atomic revision check. Changed live fees require gift acknowledgment and renewed host approval. Old preparation timers are cleared and replacement requests await acknowledgment and preparation again. Replacement produces host/player notices using existing notification types.

Cancellation retains the original queue/history record and releases reservations; allocated live requests refund the outstanding amount through their original storage pool and linked settlement entries. Each host's batch is atomic and commits only that host's changed queue/settlement rows. Cross-host results explicitly distinguish success, rejection and uncertain acknowledgment. Neither server nor modal retries uncertain writes. Confirmed successes and uncertain rows leave the current selection; confirmed rejected rows remain selected for review.
